Este proyecto no usará el plugin faro para gestionar los procesos.
Este proyecto se construirá usando Tauri como entorno de ejecución, tanstack start como framework para las vistas y tailwind como hoja de estilos.
La aplicación guardará datos tanto en una base de datos Sqlite, en local, como en archivos de tipo md.
La aplicación será de carácter multi idioma. De momento sólo usaremos castellano e inglés. Por defecto todo será en inglés. Tanto para el código fuente como para la base de datos pondremos todo en inglés (código, tablas, campos, etc). Para todos los componentes visuales en el front usaremos un archivo único i18n que contendrá para cada componente el campo "languages" que contendrá el idioma y el texto de ese componente en ese idioma. Todos los componentes que creemos tendrán este enfoque. Si te doy el componente con el texto en un idioma crea siempre la traducción al otro idioma.
Por defecto, tanto la base de datos como los archivos de la aplicación se guardarán en la misma ruta donde esté el ejecutable en las carpetas "bbdd" y "notes". En esta última irán los archivos md. Reservaremos el nombre de carpeta "docs" por si más adelante permitimos adjuntar documentos externos.
Todos los estilos se generarán en una hoja de estilos global. Todo lo que son colores y fuentes se pasarán por variables a los archivos para los "themes".
Toda la aplicación tendrá un carácter multi idioma, por lo que crearemos una carpeta "i18n" con los json de las traducciones. Para simplicar el mantenimiento de la herramienta, habrá un único json que se organizará por elementos. Cada elemento tendrá una sección "languages" donde se irán creando las traducciones. De momento, todos los textos de todos los elementos estarán en inglés y castellano. Uaremos variantes genéricas de ambos sin usar regiones, al menos por ahora. Por lo que, cada vez que te dé un elemento a crear, pondrás primero el idioma inglés y luego el castellano, siendo el inglés el idioma por defecto si no se especifica lo contrario.
Se creará una plantilla base para crear los themes. Contendrá todas las variables. Esta plantilla no se cargará nunca en una vista, será para crear los campos que debe incluir un tema, pero no tendrá valores.
Se crearán dos temas base: "Light" y "Dark". Tendrán todas las variables de la plantilla y se le asignarán valores.
El objetivo de la aplicación se servir como gestor de tareas, unificando proyectos, github y un "ToDo" personal. Además permitirá ejecutar sesiones de consola para lanzar asistentes de IA.
La aplicación será una vista que se dividirá en 2 columnas. Serán 2 divs que no tendrán espacios ni márgenes al rededor. El primero tendrá los menús, el segundo será el contenedor de la vista principal.
Aunque los elementos de los datos serán muy similares, para mantenimiento y futuros evolutivos, crearemos una tabla para cada tipo de ítem. Los ítems mantendrán una jerarquía. Para todos los items, aunque haya dado el nombre en castellano, cuando crees las tablas, pon todos los nombres en inglés, tanto para tablas como para campos.
El ítem principal será "Proyectos" y crearemos la tabla "projects" para gestionarlos. El id será autonumérico de tipo entero. Agregaremos un campo de texto que se llamará slug y que usaremos como id público. Este campo será único, para que no se repita. Si en algún momento se crea un proyecto con el mismo slug agregaremos un "_2" como sufijo. En el ejemplo he puesto un 2, pero será un contador de repeticiones. Tendrá también el campo status_id que será el FK de la tabla statuses. Tendremos los campos created_at, updated_at, closed_at y deadline que serán fechas de tipo entero. Tendrá también el campo "path" de texto con la rutas en disco duro donde estará la carptea del proyecto.
El siguiente ítem, por jerarquía, será "Épicas". Crearemos la tabla epics para este item. Será un clon de la tabla projects. Agregaremos el campo "project_id" que será el id de la tabla projects al que está asociado. Una épica siempre irá asociada a un proyecto.
El siguiente es "Macros" que tendrá la tabla macros y será un clon de projects. Agregaremos los campos "project_id" y "epic_id". Una macro puede depender de una épica y entonces el campo project_id será null. También puede depender directamente de un proyecto y el campo macro será null. Agregaremos los campos "branch" y "issue" que serán de texto para guardar las ramas e issues del repositorio. Tednrá también el campo "repo_id" que indicará el repo al que pertenecen la rama y el issue.
El último ítem será "Tareas" y tendrá la tabla tasks. Será un clon de la tabla projects. Las tareas son el desglose más pequeño del trabajo, por lo que tendrán sólo el campo "macro_id" y sólo pueden depender de una macro.
Crearemos también la tabla "repos". Tendrá también un id numérico auto incremental. Tendrá un campo texto para guardar la url del repositorio
Crearemos una tabla para cruces, con id numérico autoincremental y los campos "project_id" y "repo_id". Esta tabla servirá para decidir los repositorios que pueden pertenecer al proyecto.
Crearemos también la tabla "statuses" que tendrá el estado de los ítems. Tendrá un id numérico autoincrementeal. Un campo de texto para el "nombre", otro para "descripcion" y un campo "prority" de tipo numérico. De momento pondremos los estados:

Pondremos también la tabla "labels" que tendrá un id numérico autoincremental. Un campo "name" de tipo texto y un campo "color" también de tipo texto. Añadiremos la tabla "items_labels" que tendrá un id como campo numérico auto incremental, un campo "item_id" y el campo "item_type" que será de texto y admitirá los valores "project", "epic", "macro" o "task".
Respecto a la vista, pondremos un contenedor principal para ajustes visuales globales sin margenes y espacios. Estará dividido en dos columnas. Ambas estarán divididas por un fino borde que permitirá ser arrastrado con el ratón para cambiar el tamaño de las columnas.
En la columna o div de la izquierda, pondremos un sidebar y se verá en la parte superior el logo de la aplicación. Justo debajo tendrá el menú "Home" que aún no tendrá funcionalidad y luego se listarán los proyectos. Cada proyecto será parte del propio menú.Todos los proyectos irán dentro de un div que, si el contenido se excede del alto del div, tendrá scroll vertical. Si el texto no cabe en horizontal, se cortará con "..." al final del texto. En la parte inferior de la vista aparecerá el menú "Ajustes".
Cuando pulse en un proyecto del menú, en la vista de la derecha se mostrará un componente que se llamará main_view. Este componente tendrá dos columnas. Ambas estarán divididas por un fino borde que permitirá ser arrastrado con el ratón para cambiar el tamaño de las columnas. En la izquierda cargará el componente "ToDo" y en la derecha se cargará el componente que llamaremos "minion".
El componente ToDo será el listado de epics, macros y tasks asociadas al proyecto. Cada elemento tendrá anidado los items inferiores en jerarquía que estén asociados a los items mostrados. Cada item tendrá un espacio tabulado desde la izquierda independientemente de que esté asociado a un elemento suprior o no. Los items que tengan otros ítems anidados, podrán plegarse o expandirse.
Todos los elementos de la vista se podrán editar haciendo doble click en el elemento, lo que abrirá un popup que permitirá su edición. Permitirá editar el título o nombre, el estado con un desplegable de la tabla statuses o asociar uno de los repositorios del listado de repositorios asociados al proyecto. Si se trata de una macro o una task, permitirá escoger rama e issue que haya en ese proyecto. El listado de ramas e issues se refrescará directamente desde la API al desplegar el select para escoger.
Cuando marque una épica, macro o tarea con un estado concreto, ese estado evolucionará hacia arriba usando el que tenga priority más alto. Es decir, si establezco una task en el estado con prortity 99, todos los elementos superiores cambiarán a ese estado si su estado tiene una priority menor.
El componente "minion" tendrá dos divs horizontales (uno encima del otro), separados por una barra que permita arrastrar para establecer la altura. En el de arriba tendrá pestañas. La primera, siempre existirá y se llamará "Notes". Al entrar por primera vez, buscará en el directorio asignado en opciones (el mismo de la aplicación por defecto) un fichero con el nombre "<<tipo_item>>_<<id>>" siendo tipo project, epic, macro o task y el id el auto numérico de la base de datos. Si no existe, lo crea.
Al pulsar un proyecto, el campo notes tendrá el fichero project_<<id>>.
El div inferior será un emulador de consola de terminal. Se abrirá por defecto la ruta del proyecto que sale del campo "path" de la base de datos.
La vista completa no se destruirá de memoria para no cerrar la terminal. Quedará en memoria cada vez que se entre en un proyecto.
